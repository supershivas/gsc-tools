# GSC tools

## Description

Regroupe les différents outils de design développés pour le GSC. Premier outil : le Factsheet creator (éditeur de fiche A4 recto-verso, dataviz, export PDF).
URL de production : https://supershivas.github.io/gsc-tools/
Catégorie : **secondaire**.
Cible : **uniquement bureau** (bandeau refermable « Cette app est prévue pour un écran d'ordinateur » sur téléphone, pas d'optimisation mobile).

## Stack

JS vanilla statique, hébergé sur GitHub Pages (push sur `main` = déploiement). Aucune base de données : les données restent dans le `localStorage` (clé `factsheet-creator-v1`) ; l'export JSON des réglages (préfixe `factsheet-creator`) permet de les récupérer. Icônes : Tabler (webfont via jsDelivr). Le Factsheet creator se compile avec esbuild ; l'aperçu 3D utilise three.js (dépendance de build, empaquetée dans `factsheet/viewer3d.js`).

## Structure

- `index.html` : accueil, une carte par outil. Ajouter un outil = un dossier + une carte.
- `js/shell.js` : coque commune (en-tête, réglages, mise à jour auto, toast, bandeau bureau). Chaque page l'appelle avec `initShell({ sub })`.
- `js/app-update.js`, `css/mobile.css`, `design-tokens.json` : synchronisés depuis le design system (ne pas modifier).
- `css/tokens.css` : variables CSS dérivées de `design-tokens.json` ; `css/shell.css` : styles de la coque.
- `version.json`, `CHANGELOG.md` : version (source unique).
- `europa/europa-3d.html` : maquette 3D de la lanterne de l'Europa building (fichier autonome, three.js via CDN). Le motif des bandes obliques est calculé dans le shader de l'enveloppe (dimensions réelles de chaque fenêtre) ; elles ne s'affichent que sur la face extérieure (`FLIP_SIDED`, car three.js dessine le double-face en deux passes). Clic sur un plateau = lanterne « développée » : 11 tranches (une par plateau) découpées par des plans de coupe horizontaux qui suivent leur décalage (`slices`, `updateExplode` dans `animate`) ; re-clic, vide ou Échap la referme. Les maillages d'origine servent hors animation. Reflets : `envMap` (RoomEnvironment) sur le vitrage et l'acier seulement ; roughness/metalness du verre et opacité de Fresnel sont modifiées dans le shader de l'enveloppe. Spots : tubes horizontaux par fenêtre (`ledYs`) + halo calculé dans le même shader. Salles : `roomsGroup` (`buildCouncilRoom` niveau 5, `buildSmallRoom` niveaux 1, 3, 7, 9).
- `factsheet/` : le Factsheet creator. Sources dans `factsheet/src/`, `factsheet/app.js` est généré : après modification, `cd factsheet && npm install && npm run build` et commiter `app.js` **et** `viewer3d.js` (bundle three.js, chargé à la première ouverture de l'aperçu 3D) **et** `atelier.js`. Détails dans `factsheet/README.md`.

## Exceptions aux conventions

- L'aperçu du document (A4) du Factsheet creator garde son propre système de design (Source Sans 3 / Source Serif 4, `factsheet/src/tokens.js`) : c'est le produit, pas l'interface de l'app.
- Neutres de l'interface (`--bg`, `--line`, `--ink`…) définis localement dans `css/tokens.css` faute d'équivalent dans les tokens partagés.

- Interface du Factsheet creator : **anglais par défaut**, français en option (sélecteur dans la barre), à la demande du propriétaire ; déroge à « interface en français ». Le reste de la coque (en-tête, réglages) reste en français. Les textes du code sont en français et servent de clés : dictionnaire FR → EN dans `factsheet/src/i18n.js` (toute nouvelle chaîne d'interface doit y être ajoutée ; une valeur créée dans le document doit passer par `t()`).

- **Atelier** (`factsheet/atelier.html`, lien dans les réglages) : publie les images du document dans `factsheet/assets/` et les projets dans `factsheet/projects/` par un commit sur `main` (API Git de GitHub, `src/github.js`). Jeton personnel à droits fins gardé dans le `localStorage` sous `gsc-tools-github-token` (clé volontairement hors du préfixe `factsheet-creator`, donc jamais exportée). Après publication, le document ne garde que le chemin (`assets/<hash>.<ext>`), une fois Pages à jour.

- **Menus de l'en-tête** : `initShell({ menus, settingsExtra })` (`js/shell.js`) ; le Factsheet creator les déclare dans `window.FS_UI` (`factsheet/src/main.js`), lu par `factsheet/index.html`. Les réglages (roue crantée) restent l'unique accès aux réglages ; la langue y est une section ajoutée par `settingsExtra`.
- **Glisser-déposer avec aperçu en direct** (`main.js`, `tree.js`) : pendant le geste, `ctx.preview(fn)` dessine une copie du document avec le déplacement appliqué ; relâcher valide, Échap annule. Sections et sous-sections se glissent par leur titre sur la page (ou la poignée de la barre au survol), colonnes par la poignée de la barre ; une colonne se vise sur toute la hauteur de sa rangée, pas seulement sur son contenu. Les cibles sont désignées par identifiant (`id` de section et de sous-section). L'élément glissé est « pris » : son rendu réel (clone, `.drag-obj`) suit le pointeur, son emplacement d'arrivée est en pointillés (`.drag-live`).
- **Espacement** : `doc.density` (`tight` 75 %, `normal`, `loose` 125 %) multiplie les écarts entre sections, sous-sections et colonnes (`DENSE_KEYS` dans `tokens.js`, arrondis à la grille de 3 px) ; `setDensity` est appelé au début de `renderDocument` et `columnWidth`, donc l'export suit. « Marges et espaces » (bouton et densités dans la barre, aussi dans Affichage ; `syncSpacingCtl`) est un filigrane de l'aperçu (`drawSpacing`, `main.js`), hors des pages. Boutons « + » (`hover.js`, `.hv-add`) : fantômes à la hauteur d'un bloc par défaut, sous la dernière section de la page / dernière sous-section de la section seulement, et s'il reste de la place. Cmd/Ctrl + molette = zoom continu (`main.js`). Image du header : hauteur 132 px, largeur selon l'image (`.hd-img`).
- **Historique** (`main.js`, `record` / `goTo`) : un instantané du document après chaque `ctx.changed()` (frappe regroupée sur 1 s) ou `ctx.restructure()` ; 100 pas max, images en data URL remplacées par un numéro dans les instantanés. Boutons au centre de l'en-tête (`FS_UI.center`, créneau `center` de `initShell`), menu Édition (`disabled()` et `hint` pris en charge par `js/shell.js`), Cmd/Ctrl + Z / Maj + Z / Y hors champs de saisie. Panneau « Historique des modifications » (icône horloge, `toggleHistory`) : un libellé par pas (`describe`, première différence entre deux états), clic = retour à ce pas. Message de déplacement/suppression : `noteToast`, petit, bas gauche, 6 s. Il n'y a plus de panneau « Document » : couleurs, format des nombres et nom du fichier sont dans Édition / l'en-tête ; un seul thème (`doc.theme` reste stocké).
- **Palette à deux tons** : `toneKeys` (`tokens.js`) = couleurs pleines + blanc + teintes légères `tint-<couleur>` (20 %) ; c'est la seule liste de fond, contour, texte et séries. Les sélecteurs affichent deux rangées alignées (`swatches` dans `props.js`).
- **Cadre de sélection** : calque `.sel-layer` superposé à la page (`drawSelection`, `main.js` ; styles `css/sel.css`), une section est encadrée à la largeur des marges ; variante retenue « Halo » (`SEL_STYLE`, onde douce en boucle), cadre à `SEL_GAP` = 3 px autour de l'élément ; autres variantes dans le Labo (sujet « Sélection »).
- **Panneaux** : propriétés (droite) et structure (gauche) en cartes repliables (variante B du Labo) ; `card()` dans `props.js` (état replié gardé en mémoire), `.pp-*` et `.tn-*` dans `css/app.css`.
- **Déplacements** : déposer un contenu sur une colonne **échange** les deux contenus (alignements inclus) ; une sous-section se range dans n'importe quelle section. Tout passe par `ctx.moved()` (`main.js`) qui garde un instantané pour « Annuler le déplacement » (effacé à la modification suivante). Effets de bord : largeur de colonne différente (dataviz et images se redessinent), page de destination qui déborde (avertissements existants), section laissée vide (conservée).

- **Suppression** : `ctx.remove(path)` (`main.js`, touche Suppr / Retour arrière hors saisie et fenêtres ouvertes) passe par `ctx.moved()` donc annulable ; supprimer une colonne rend sa place aux autres (`removeCol` : 3 → `1-1`, 2 → `1`), la dernière colonne supprime la sous-section.
- **Labo** (`factsheet/labo.html`, lien dans les réglages) : banc d'essai des cartes (`src/card.js`, `css/card.css`, pas encore dans l'éditeur) et du chiffre clé ; ajouter un sujet ou une variante = une entrée dans `TOPICS` de `src/labo.js` (sujet « Propriétés » : variantes du panneau dans `src/labo-panel.js`, `panel: true` masque options et largeur). Une carte adoptée devient un type de contenu (voir `src/figure.js` pour le modèle).
- **Cadres** (`stroke`, `strokeColor`, `fillColor` sur sections, sous-sections et colonnes ; fond : `none`, `white`, une couleur ou `tint-<couleur>`, indépendant du contour) : trait 0,5 pt, coins de 3 px (`STROKE.radius`), le cadre est aligné sur les marges et le contenu est en retrait de `GAP.boxPad` (un fond sans contour garde ce retrait, trait transparent) ; les largeurs transmises aux dataviz/images sont réduites par `insetW` (`isBox`, `columnWidth()` dans `render.js` pour la largeur réelle). L'ancien `fill` booléen est migré en `fillColor` (`state.js`, `oldBoxes`). Une section a en plus son fond de bande (`bg`, teintes ou couleurs).
- **Dataviz** : toute modification passe par l'éditeur de dataviz ; le panneau de droite ne garde que le bouton qui l'ouvre. Le chiffre clé n'est plus une dataviz (`col.type = 'figure'`) ; les anciens fichiers sont migrés dans `state.js`.

- **Couleurs** : 5 couleurs par thème (`THEMES` dans `tokens.js`), blanc toujours disponible, jusqu'à 7 couleurs ajoutées par document (`doc.colors` clés `x1`…, noms dans `doc.colorNames`). Les fonds de section sont des teintes calculées (`tint-<clé>`, `tintOf`). Chaque choix de couleur (propriétés, barre au survol, éditeur de dataviz) a un bouton « + » qui ouvre `src/palette.js` (modifier, renommer — y compris les couleurs du thème, `doc.colorNames` —, ajouter, supprimer). Édition par `src/colorpicker.js` (RVB, TSV, CMJN, hexadécimal ; le CMJN est une conversion simple sans profil ICC, les couleurs restent stockées en hexadécimal et le PDF exporté reste en RVB). Le thème a 5 couleurs dont `grey` (gris clair, ex-`lavender`, migré) ; le header par défaut est `grey` avec texte `blue`. Les anciennes clés (`deep`, `steel`, `tint*`, `lavender`) sont migrées dans `state.js` (`oldColors`) ; supprimer une couleur ajoutée fait passer ses usages en bleu (`removeColor`).
- **Cartes** : type de contenu `card` (`src/card.js` rendu, `src/cardmodel.js` options et contenu). Le type par défaut suit la largeur de la colonne (`cardPresetFor` : ≥ 450 px image à côté, ≥ 300 px image en haut, sinon icône en tête) tant que `card.auto` est vrai ; toucher à une option le passe à faux. Le contour d'une carte est une option de la carte (pas le contour de colonne).

## Pièges connus

- Rien de ce qui est ajouté ou retiré à chaque rendu ne doit changer la taille de `#stage` (ni `#warnings`, ni la barre au-dessus) : un `ResizeObserver` relance le rendu et la page saute. La légende « Marges et espaces » vit dans la barre (`.bar`), de hauteur fixe ; `drawPreview` restaure aussi le scroll.
- Le Factsheet creator imprime le PDF via `window.print()` : l'en-tête, le bandeau et le toast sont masqués en `@media print` (`factsheet/css/app.css`) ; tout nouvel élément fixe de la coque doit l'être aussi.
- L'aperçu 3D dessine chaque page via un SVG `<foreignObject>` (`factsheet/src/raster.js`) : le CSS du document et les polices latin y sont embarqués ; un nouveau style de page doit rester dans `doc.css`. L'overlay `.v3d` est masqué en `@media print`.
- Les images publiées sont des chemins relatifs : l'aperçu 3D les réinjecte en data URL (`raster.js`), l'export PDF les charge normalement. Le déploiement de Pages prend ~1 min : l'Atelier attend que les fichiers répondent avant de remplacer les data URL du document.
- Le logo a 4 versions (`header.logos` + `header.logoVariant`) et le header une bibliothèque d'images (`header.images` + `imageId`), stockées en data URL dans le `localStorage` : un avertissement s'affiche si le stockage du navigateur est plein. Les 4 logos d'origine (`DEFAULT_LOGOS`) et l'image par défaut du header (`assets/Asset 1.svg`, id `img-default`, toujours en tête de bibliothèque) sont des fichiers du dépôt, rétablis par `migrate` si le document ne les a pas : les logos ne se retirent pas (on charge une autre image à leur place, « Rétablir l'original »), l'image par défaut ne se modifie ni ne se supprime.
- Les réglages sont un `<dialog>` modal : il bloque les clics sur l'en-tête tant qu'il est ouvert (Échap ou fond pour fermer).
