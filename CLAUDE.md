# GSC tools

## Description

Regroupe les différents outils de design développés pour le GSC. Premier outil : le Factsheet creator (éditeur de fiche A4 recto-verso, dataviz, export PDF). Autres outils : Europa 3D, Donut export, PEC organigramme (organigramme A4 au gabarit PEC, PDF CMJN), Batch Logo Export (script Illustrator à télécharger, avec mode d'emploi).
URL de production : https://supershivas.github.io/gsc-tools/
Catégorie : **secondaire**.
Cible : **uniquement bureau** (bandeau refermable « Cette app est prévue pour un écran d'ordinateur » sur téléphone, pas d'optimisation mobile).

## Stack

JS vanilla statique, hébergé sur GitHub Pages (push sur `main` = déploiement). Aucune base de données serveur : les documents du Factsheet creator restent dans le navigateur, en IndexedDB (base `factsheet-creator`, un document par onglet) avec un miroir du document actif dans le `localStorage` (clé `factsheet-creator-v1`) ; l'export JSON des réglages (préfixe `factsheet-creator` + clé `factsheet-creator-workspace` fournie par la page) permet de les récupérer. Icônes : Tabler (webfont via jsDelivr). Le Factsheet creator se compile avec esbuild ; l'aperçu 3D utilise three.js, l'export PDF pdf-lib (dépendances de build, empaquetées dans les bundles).

## Structure

- `index.html` : accueil, une carte par outil. Ajouter un outil = un dossier + une carte.
- `js/shell.js` : coque commune (en-tête, réglages, mise à jour auto, toast, bandeau bureau). Chaque page l'appelle avec `initShell({ sub })`.
- `js/dialog.js` : modales `alertModal` / `confirmModal` / `promptModal` (styles `.modal` dans `css/shell.css`). Jamais `alert`, `confirm` ni `prompt` du navigateur ; dans le Factsheet creator, passer par `factsheet/src/dialogs.js` (boutons traduits), toujours avec `await`.
- `js/app-update.js`, `css/mobile.css`, `design-tokens.json` : synchronisés depuis le design system (ne pas modifier).
- `css/tokens.css` : variables CSS dérivées de `design-tokens.json`, plus les variables locales de l'interface du Factsheet creator (poignées, rouge d'alerte, ombres, échelle de tailles `--fs-*`, arrondis `--radius-*`) ; `css/shell.css` : styles de la coque.
- `version.json`, `CHANGELOG.md` : version (source unique).
- `europa/europa-3d.html` : maquette 3D de la lanterne de l'Europa building (fichier autonome, three.js via CDN). Détails dans `europa/README.md`.
- `donut/donut-export.html` : export d'un graphique en anneau (PNG/JPG, versions A/B/C), fichier autonome branché sur la coque ; ses styles sont limités à `.app` ; fichiers exportés nommés `UA_AAMMJJ_nom` ; données dans `localStorage` clé `donut-export-v1`, hors export des réglages.
- `illustrator/` : page statique du script Illustrator **Batch Logo Export** : `index.html` (mode d'emploi, branché sur la coque) et `batch-logo-export.jsx` (le script, téléchargeable ; ne pas le renommer sans mettre à jour le lien). Aucune donnée.
- `organigramme/` : **PEC organigramme** (sans build, modules ES). Détail dans la section « PEC organigramme » plus bas.
- `scripts/verifier.mjs` : vérifications rapides (fichiers de la structure, version = tête du changelog, règles de PEC organigramme, pas de version flottante) ; lancé aussi par le workflow de tests.
- `factsheet/` : le Factsheet creator. Sources dans `factsheet/src/` (`main.js` = état du document, `ctx` et assemblage ; un module par responsabilité dans `src/editor/`, `src/props/`, `src/viz/`, `src/pdf/`). Les bundles `app.js`, `viewer3d.js`, `atelier.js`, `labo.js` et `pdfexport.js` sont générés : après toute modification des sources, `cd factsheet && npm install && npm run build` et commiter les cinq. Pages : `index.html` (éditeur), `labo.html`, `atelier.html`.
- **Images du dépôt** : `factsheet/assets/` est rangé en `logos/<famille>/` (fichiers dont le nom contient `default`, `mono`, `white` ou `neg`/`negative`, ex. `pec_neg_h_rgb_en.svg`), `header/<dossier>/` et `others/` (images du corps). Ajout **à la main** sur GitHub ; `assets/index.json` (liste lue par l'app, GitHub Pages ne liste pas un dossier) est **généré à chaque déploiement** par `scripts/assets-manifest.mjs` (étape de `pages.yml`, pas de commit automatique ; ne pas le modifier à la main). Lecture : `src/assetlib.js` ; vignettes et marqueur « non stockée » (`cloud-off`, image en data URL) : `src/props/assetgrid.js` ; carte « Document images » : `props/document.js`. Anciens chemins (`assets/<hash>.png`, `assets/Asset 1.svg`) migrés par `upgradeAsset` (`state.js`) : ne jamais les retirer de `LEGACY_ASSETS`.
- **Espace de travail du Factsheet creator** (onglets) : `src/editor/workspace.js` (onglets, brouillons, récents, `ctx.tab()` / `ctx.tabs()` / `ctx.getDocOf(id)`), `src/editor/tabs-ui.js` (barre `#fsTabs`), `src/wsstore.js` (IndexedDB, partagé avec l'Atelier). Base `factsheet-creator` v1 : `tabs` `{ id, schemaVersion, doc, dirty, savedAt }`, `meta`.`workspace` `{ schemaVersion, order, active, legacySig, views: { [id]: { sel, zoom, spacing, collapsed } } }`, `recents` `{ fileId, name, at, doc }` (10 max, **hors export des réglages**). `doc.fileId` (ajouté par `migrate`) identifie un fichier : le rouvrir bascule sur son onglet. Détail dans `docs/architecture.md` (« Espace de travail »).
- **Tableau du Factsheet creator** (`factsheet/src/table/`) : type de colonne `table` ; `model.js` (opérations pures, invariant « une case = une cellule », `repairTable` à l'ouverture), `render.js` (grille CSS + calque SVG des traits calé par `measure()`, jamais de bordures CSS), `editor.js` + `grid-ui.js` (éditeur modal, coque `.ve`, historique propre), `panel-style.js` (cartes Remplissage / Contours / Préréglages : fonds par cellule, ligne, colonne, pied ; surcharges d'arêtes `tb.edges` sur la sélection ; toute nouvelle clé de couleur du tableau passe par `remapTableColors`), `tabular.js` (import CSV/TSV avec aperçu, export ; nombres réécrits au séparateur décimal du document), `paste.js` (collage HTML Word/Excel/Sheets réduit à table/tr/td, fonction pure ; le HTML du presse-papiers n'est jamais inséré tel quel). Poignées de largeur : `editor/split.js` (commun avec `handles.js`). Cellule : `st` (sous-ensemble `CELL_STYLES`), `fg`, `pad`, `av` ; colonne numérique `cols[].num`. Plan par phases : `factsheet/docs/plan-tableau.md`.
- **Documentation détaillée du Factsheet creator** : `factsheet/README.md` (phases, format du texte, dataviz, tests) et `factsheet/docs/architecture.md` (une description par fonctionnalité : espacement, glisser-déposer, historique, texte riche, dataviz, couleurs, export PDF, aperçu 3D…). La lire avant de toucher à une fonctionnalité ; la mettre à jour quand une décision durable est prise.

## PEC organigramme (`organigramme/`)

Un seul écran : panneau d'édition à gauche, aperçu A4 en direct à droite, export PDF CMJN. Interface en français, mode sombre (`prefers-color-scheme`), la feuille reste blanche.

- `index.html` + `boot.js` : `boot.js` lit `version.json`, pose une **import map** (`org/…` → `organigramme/js/…?v=<version>`, `gsc/…` → `js/…?v=<version>`) puis charge CSS et `js/main.js`. Les modules s'importent donc par `org/x.js` / `gsc/x.js`, jamais par chemin relatif ; **tout nouveau module s'ajoute à `MODULES` dans `boot.js`** (le vérificateur le contrôle).
- `js/model.js` : schéma, gabarit par défaut (`defaultDoc`, **structure et styles du PEC mais aucun texte** : tout champ est vide, jamais de texte d'exemple dans le code, les aides sont des `placeholder`), `migrate`, `fileStem`. `js/layout.js` : mise en page pure (cotes du gabarit dans `T`, en points) qui rend une liste d'éléments ; `js/render.js` (aperçu SVG + mesure du texte) et `js/pdf.js` (pdf-lib) dessinent **la même liste** : ne jamais dessiner dans l'un sans l'autre. `js/theme.js` : couleurs (CMJN + écran) et polices. `js/store.js` : `localStorage`, historique, fichiers JSON. `js/main.js` : état et interface.
- `fonts/` : polices statiques officielles d'Adobe (Source Sans 3 Bold, Source Serif 4 It / SemiboldIt, OFL), celles du gabarit, servies à l'écran et incorporées au PDF. Ne pas les remplacer par `factsheet/fonts/pdf` (autre taille optique, sans crénage : les largeurs ne correspondent plus au gabarit).
- `vendor/` : pdf-lib 1.17.1 et @pdf-lib/fontkit 1.1.1 (copies figées, approuvées par le propriétaire, chargées au premier export). Profil ICC : celui du Factsheet creator (`factsheet/icc/`).
- **Données** : `localStorage` clé `pec-organigramme-v1` = `{ schemaVersion: 1, savedAt, doc }`, incluse dans l'export des réglages (préfixes dans `js/shell.js`). `doc` = `{ schemaVersion, title, page: { orientation, fit, equalHeights }, logo, image, assets, levels[] }` ; `levels[]` = `{ id, boxes[], rails }` (`rails` = hauteur 0,15–0,85 du trait horizontal des liens entrant dans le niveau, par groupe ; clé = id du cadre parent ou `auto`, défaut 0,505) ; `boxes[]` = `{ id, title, tone: dark|mid, align: left|center, lead: { name, role } | null, link: { to: 'auto'|'none'|<id d'un cadre du niveau du dessus>, dash }, groups[] }` ; `groups[]` = `{ id, title (vide = sans barre), people[] }` ; `people[]` = `{ id, name, role, emph }`. `logo` / `image` = `{ asset, name, ratio, w (points), x, y }` avec `x`/`y` nuls = placement automatique (logo en haut à gauche, image en haut à droite) ; `assets` = data URL par clé. Fichier enregistré : `{ app: 'pec-organigramme', schemaVersion, exportedAt, doc }`. Toute lecture passe par `migrate` ; ne jamais renommer une clé.
- **Liens entre niveaux** (`layout.js`, `groupsFor` / `linkGroup`) : chaque cadre se relie au niveau non vide du dessus. `auto` = cadres sans parent choisi, reliés à tous les cadres du dessus qui n'ont pas d'enfant choisi (à tous s'il n'en reste aucun) ; un id = trait vers ce cadre seul ; `none` = pas de trait. Un id qui n'est plus au niveau du dessus retombe en `auto` (migrate et mise en page). Les traits portent un `link` (sélection et glisser du rail dans l'aperçu : zone de clic invisible `.link-hit`, jamais exportée ; le PDF l'ignore). Trait en tirets : motif `DASH` de `theme.js`, partagé écran et PDF. Le trait horizontal d'un groupe est plein partout où passe au moins un lien plein.
- **Règles** : couleurs du document uniquement par `COLORS` (EU Blue 100-80-0-0 et ses teintes 60 % / 25 %, blanc), en `DeviceCMYK` dans le PDF ; toute modification passe par `commit()` (historique, enregistrement, aperçu) ; pas d'`innerHTML` ; « ajuster à la page » réduit corps et hauteurs, pas les largeurs.
- **Limites connues** : logo et image sont incorporés tels quels (un PNG reste RVB, un JPEG CMJN reste CMJN, un SVG est converti en PNG à ~600 ppp) ; le PDF déclare le profil FOGRA39 mais n'est pas certifié PDF/X.
- **Vérifier** : `node scripts/verifier.mjs`, puis l'outil ouvert en 1280 px et 375 px sans erreur de console, et un export PDF comparé au gabarit.

## Exceptions aux conventions

- L'aperçu du document (A4) garde son propre système de design (Source Sans 3 / Source Serif 4, `factsheet/src/tokens.js`) : c'est le produit, pas l'interface de l'app.
- PEC organigramme : neutres du mode sombre définis dans `organigramme/css/organigramme.css` (absents des tokens partagés) ; boutons d'icône de 32 px à la souris, 44 px au toucher (`pointer: coarse`), pour garder des lignes de personnes denses.
- Neutres de l'interface (`--bg`, `--line`, `--ink`…) et variables locales (`--handle`, `--danger`, `--fs-*`, `--radius-xs`…) définis dans `css/tokens.css` faute d'équivalent dans les tokens partagés. Pas de valeur de couleur, de taille de police ou d'arrondi en dur dans `factsheet/css/app.css`, `sel.css`, `labo.css` : utiliser ces variables.
- Interface du Factsheet creator : **anglais par défaut**, français en option (sélecteur dans la barre), à la demande du propriétaire ; déroge à « interface en français ». Le reste de la coque (en-tête, réglages) reste en français. Les textes du code sont en français et servent de clés : dictionnaire FR → EN dans `factsheet/src/i18n.js` (toute nouvelle chaîne d'interface doit y être ajoutée ; une valeur créée dans le document doit passer par `t()`). Clé sans espace au début ni à la fin, jamais en double (esbuild avertit : `Duplicate key`).
- **Atelier** (`factsheet/atelier.html`) : publie les images dans `factsheet/assets/others/` et les projets dans `factsheet/projects/` par un commit sur `main` (API Git de GitHub, `src/github.js`). Jeton personnel à droits fins gardé dans le `localStorage` sous `gsc-tools-github-token` (hors du préfixe `factsheet-creator`, donc jamais exporté).
- **Menus de l'en-tête** : `initShell({ menus, settingsExtra })` ; le Factsheet creator les déclare dans `window.FS_UI` (`editor/menus.js`). Les réglages (roue crantée) restent l'unique accès aux réglages.
- Dépendances de build du Factsheet creator approuvées par le propriétaire : `three`, `pdf-lib` + `@pdf-lib/fontkit`, `d3-hierarchy`, `d3-sankey`, `@playwright/test`, `prettier`. Toute autre dépendance : demander.

## Règles impératives du Factsheet creator

Détail et raisons dans `factsheet/docs/architecture.md`.

- **Rouge = action** : le rouge d'accent ne marque que ce qui agit (bouton principal) ; états sélectionnés (onglets, espacement, cartes de type) et jauges en neutre ; orange/rouge d'alerte seulement pour un dépassement.
- **Tout nouvel élément visuel du document doit rester lisible par l'export PDF** : éléments HTML/SVG réels, jamais de pseudo-élément, d'ombre ni de dégradé CSS ; tout opérateur de couleur du PDF passe par `makeInk`, le fond perdu par `bleedFor`.
- **Un seul chemin d'export** : `factsheet/src/pdf/pdf.js` (pas de `window.print`) ; tout fichier enregistré ou exporté se nomme par `fileStem` (`titre_AAMMJJ_HHMM.extension`).
- **Pas d'état global pendant le rendu** : tout passe par le contexte de rendu (`renderCtx`, `env.rc`) ; hors rendu, passer le document (`columnWidth(doc, …)`, `densityGaps(doc.density)`). Deux documents doivent pouvoir se rendre entremêlés (`tests/isolation.spec.js`).
- **Glisser-déposer** : l'élément « pris » suit le pointeur avec une ombre, le reste se réarrange en direct, l'arrivée est en pointillés, Échap annule, un clic simple n'est jamais un glissement. Moteur commun `editor/dnd.js` ; dataviz : `vizreorder.js`.
- **Aucun module ne garde le document** : lire `ctx.getDoc()` / `ctx.getSel()` / `ctx.tab()` à chaque appel (le document change avec l'onglet) ; un état propre au document (historique, zoom, filigrane…) va dans l'onglet (`workspace.js`), pas dans une variable de module.
- **Déplacements et suppressions** passent par `ctx.moved()` (annulables) ; toute modification du document appelle `ctx.changed()` ou `ctx.restructure()` (historique).
- **Nouvel élément redimensionnable** : poignée `div` vide dans `editor/handles.js` (`dragSplit`), avec retour en direct ; hors export.
- **Nouvelle accolade de mise en forme en ligne** : `inlineMk`, `stripInline`, `htmlToMk`/`fmtStyle`. **Nouveau style de paragraphe** : `PSTYLES` + `TYPE` + `doc.css` + `app.css` + traduction. **Nouvelle sérialisation XML** : via `XML_BAD` (`raster.js`). **SVG importé** : toujours par `cleanSvgTree`.
- **Champ de dataviz** : chaque champ de `fields` déclare sa carte par `g:` (`struct`, `dims`, `axes`, `labels`, `colors`, `bracket`, `data`) selon la règle de `docs/architecture.md`, sans rangement par défaut (un test refuse l'oubli) ; son ordre dans la carte se règle dans `FIELD_ORDER` (`src/vizgroups.js`).
- **Dataviz** : toute modification passe par l'éditeur de dataviz ; nouvelle légende par `drawLegend`/`drawLegendWrap` ; nouveau choix d'icône par `iconSelect` ; texte du document : champs `<textarea class="ml">` et `white-space: pre-line`.
- **SVG non rognés** : `.page svg, .viz-sheet svg { overflow: visible }` (`doc.css`) ; ne jamais s'appuyer sur le rognage par défaut d'un SVG.
- **Choix de type** : `richSelect` avec icônes ; 2–3 valeurs courtes : `pair` ; jamais un bouton dans un `<label>`.
- **Factsheet par défaut** (`defaultDoc`, `state.js`) : recto et verso remplis sans avertissement de débordement ; relire les avertissements si on y change des tailles.
- **Images à l'import** : toute image lue dans un projet passe par `safeImgSrc` (`state.js`, appelé par `migrate`) : seules `data:image/…` et les chemins relatifs du dépôt (`assets/…`) sont gardées, jamais une adresse distante (pixel espion). Toute nouvelle source d'image d'un document doit y passer.
- **Identifiants stables** : ne jamais renommer une clé existante (`sub.layout`, couleurs, gabarits) ; les anciens fichiers sont migrés dans `state.js` (`migrate`).

## Pièges connus

- Avant chaque push du Factsheet creator : `cd factsheet && npm run check && npm test` (`check` vérifie aussi Prettier sur `src/` : `npx prettier --write src`). Une capture de référence (`factsheet/tests/references/`) ne se met jamais à jour pour « faire passer » un test ; seules les captures de l'interface peuvent changer, pas celles des pages du document. Élargir un panneau change le zoom « Ajuster » donc les captures des pages : à éviter.
- Mesure de texte (`mw`, `viz/util.js`) : le canvas mesure à une taille de référence fixe (200 px) puis met à l'échelle ; ne jamais mesurer à `taille × 100`. Ne pas imposer `textLength` aux textes SVG.
- Cache de GitHub Pages : 10 min (`max-age=600`). `factsheet/index.html` charge CSS, `app.js` et `js/shell.js` avec `?v=<version>` (petit script de démarrage), les bundles à la demande (`viewer3d.js`, `pdfexport.js`) aussi (`loadBundle`, `editor/export-ui.js`). Tout nouveau CSS/JS du Factsheet creator passe par ce démarrage.
- Déploiement Pages : l'identifiant d'un déploiement est le SHA du commit. Si un déploiement bloqué est annulé, relancer le même commit échoue (« Deployment cancelled ») : pousser un nouveau commit.
- Rien de ce qui est ajouté ou retiré à chaque rendu ne doit changer la taille de `#stage` (ni `#warnings`, ni la barre au-dessus) : un `ResizeObserver` relance le rendu et la page saute. La barre (`.bar`) a une hauteur fixe ; `draw` (`editor/preview.js`) restaure le scroll.
- Cmd/Ctrl + P ouvre la fenêtre d'export (`editor/shortcuts.js`) ; l'impression du navigateur reste possible par son menu : tout élément fixe de la coque (en-tête, bandeau, toast, `.v3d`) doit être masqué en `@media print` (`factsheet/css/app.css`). Ne pas réintroduire de rendu d'impression CSS.
- L'aperçu 3D dessine chaque page via un SVG `<foreignObject>` (`src/raster.js`) : un nouveau style de page doit rester dans `doc.css`. Les images publiées sont des chemins relatifs, réinjectés en data URL pour l'aperçu 3D ; Pages met ~1 min à se mettre à jour (l'Atelier attend). En rendu logiciel (headless), l'aperçu 3D tourne à ~1 image/s : longs délais dans les tests.
- Le logo a 4 versions (`header.logos`) et le header une bibliothèque d'images (`header.images`), en data URL dans le document (IndexedDB) : un avertissement s'affiche si le stockage est plein (`storage.ok`). Logos d'origine et image par défaut (`assets/Asset 1.svg`) sont des fichiers du dépôt rétablis par `migrate`.
- Le calque de dépassement (`.ovf`, `editor/preview.js`) contient une copie de la page (`.page.ovf-clone`) : toute requête sur `.page` dans le stage doit l'exclure (`.page:not(.ovf-clone)`), sinon elle devient une cible de glisser-déposer ou de mesure.
- Onglets : Ctrl/Cmd + T et + W sont réservés par le navigateur (jamais reçus par la page) : raccourcis Alt (⌥) + N / W. **Raccourcis à lettre : toujours la lettre produite (`letterOf`, `e.key`), jamais `e.code` seul** (AZERTY). Pas de changement d'onglet pendant un geste, une fenêtre ou l'éditeur de dataviz (`ws.busy()`).
- `factsheet/index.html` attend `window.FS_READY` (lecture d'IndexedDB) avant `initShell`. Les tests qui lisent ou écrivent `factsheet-creator-v1` touchent le miroir du document actif ; une clé modifiée hors de l'éditeur est adoptée par l'onglet actif au lancement (`legacySig`). `seed` (tests/helpers.js) vide la base.
- Les réglages sont un `<dialog>` modal : il bloque les clics sur l'en-tête tant qu'il est ouvert.
- Pas de validateur PDF/X libre : vérifier au moins une fois un export avec le contrôle en amont d'Acrobat.
